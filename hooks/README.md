# Hook internals

`hooks/laya.ts` is the plugin's function-hook module (`hooks/hooks.json` lists
it). It is a thin adapter around the code in `src/`: it reads the plugin
settings, hands `session.compact` transcripts to `compact()`, and maps the result
back onto session messages. User and assistant text is never touched. See the
[root README](../README.md) for what it does and how to install it.

## Events

| Event | What the hook does |
| --- | --- |
| `session.compact` | Scores the tool calls through Laya (`$.http.fetch`, 30 s timeout per request). Returns the pruned messages, or falls back to Claude Code's built-in summary on any error or when the reduction is below `minReductionRatio`. Every outcome is recorded in the stats database. |
| `turn.complete` | Requests a compaction when `context.percent` reaches `compactAtPercent` (with an in-flight guard). |
| `session.start` | Registers the `/laya-status` and `/laya-stats` commands. |
| `command.run` | `/laya-status` calls `<server>/health`; `/laya-stats` runs the stats helper. |
| `config.set` | Validates and normalizes the "Laya server URL" row before it is saved. |

## Why the stats go through a child process

Hook modules run in a sandbox with no Node built-ins, so they cannot open SQLite.
The hook runs `node dist/stats-cli.js record|report` with `$.process.run`, sending
the compaction as JSON on stdin. `dist/` is built by `npm run build`; the plugin is
loaded in place, so it is what runs. A failure to record is logged with `$.ui.log`
and never affects the compaction. The database schema lives in `src/stats.ts`, the
pure record types (safe to import from the sandbox) in `src/stats-record.ts`.
